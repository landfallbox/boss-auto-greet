# Intent：每日投递统计与 HTML 日报

> 状态：已确认（2026-10-29）
> 日期：2026-10-29

## 当前问题

1. 每天自动打招呼跑完后，**不知道今天具体投了哪些岗位**——`state.json` 只存 `sent` 计数和 `seen`（标题+城市）列表，且**当天跨天即重置**，历史全部丢失。
2. **被跳过的岗位不留痕**：城市不符 / 经验不符 / JD 缺硬技能 / 找不到按钮等原因只在终端打印，跑完就没了。
3. 没有任何**回顾手段**：无法回答"今天投了多少、都投在哪些城市、哪些岗位被哪条规则过滤掉了、过滤器是不是太激进"，更谈不上基于数据的改进。

## 期望结果

1. **投递明细落盘**：每次成功打招呼的岗位记录 标题 / 城市 / 薪资 / 时间，按天存为 `stats/YYYY-MM-DD.json`。
2. **跳过明细落盘**：每个被跳过的岗位记录 标题 / 城市 / 薪资 / 跳过原因（pre 过滤细分原因 / JD 缺哪个硬技能 / 无按钮 / 详情打不开等），同样按天落盘。
3. **HTML 日报**：每次跑完自动在 `reports/YYYY-MM-DD.html` 生成一份可直接浏览器打开的日报，包含：
   - 当日概览：投递数、跳过数、各跳过原因占比
   - 投递岗位清单（城市 / 薪资 / 时间）
   - 跳过岗位清单（含原因）
   - **自动生成的简单改进建议**（只基于**当天**数据：跳过原因分布、城市分布、薪资分布等；因不统计回复，建议不含回复率）
4. **半周总结报告**：周二结束、周五结束（即当天跑完时）各生成一次，分别覆盖 周一~周二、周三~周五，跨天汇总统计并基于汇总数据给出改进建议。
5. 历史数据按天累积、**永久保留**（不清理），可回看往日的 JSON / HTML。

## 受影响系统

| 文件 | 影响 |
|------|------|
| `boss_auto.py` | 主循环中补记录逻辑（sent / skip 时写当日统计）；跑完触发报告生成 |
| `bosslib.py` | 可能需要新增/调整读取函数（如 pre 过滤细分原因），视 spec 而定 |
| `config.py` | 可能新增统计相关开关（如是否记录跳过、报告输出目录），视 spec 而定 |
| 新增 `stats/` 目录 | 每日统计 JSON（数据文件） |
| 新增 `reports/` 目录 | 每日 HTML 日报 + 半周总结 HTML（产物文件） |
| 新增统计/报告模块 | 具体文件名与拆分方式在 spec 中定 |
| `.gitignore` | 新增 `stats/`、`reports/`（已确认不入库） |

## 数据 / 技术约束

- 单机运行：PC 通过 USB + ADB 驱动真机，无服务器、无网络依赖；报告必须是**本地可直接打开**的 HTML（不依赖 CDN 的离线可用更好）。
- 数据量小：每天 ~120 条投递 + 若干跳过，JSON 文件足够，无需数据库。
- 与现有 `state.json` 风格一致（纯 Python 标准库读写，不引入新依赖为宜）。
- 风控约束：统计功能**不得**额外驱动 App 页面（不读聊天页、不点消息 tab），只在现有流程的数据上落盘。
- `--dry` 空跑不实际打招呼，其数据不能混入真实投递统计。
- 数据永久保留，不做清理/过期逻辑。

## 明确不做的事

- **不统计回复**（用户明确：回复不统计了，只统计投递/跳过等其他信息）。
- 不自动读取 BOSS 聊天列表 / 消息页。
- 不自动修改 `config.py` 过滤参数（建议只给方向，人拍板）。
- 不做 Web 服务 / 仪表盘 / 图表库重依赖（HTML 报告保持轻量）。
- 不做多账号 / 多设备聚合。

## 已确认决策（2026-10-29 用户拍板）

1. **数据与报告不入库**：`stats/`、`reports/` 加入 `.gitignore`（与 `state.json` 一致）。
2. **数据永久保留**：按天分文件无限累积，不清理。
3. **报告生成时机**：每次跑完自动生成；若中途有中断，报告基于已累积的记录生成（补在后面），后续运行继续追加记录并更新报告，无需独立补生成命令。
4. **建议输入范围**：日报建议只针对当天；另在周二结束、周五结束各生成一次**半周总结**（周一~周二、周三~周五），建议基于该半周的汇总数据。
